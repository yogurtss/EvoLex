# EvoLex 发明专利技术交底书（双层静态可视化增量版）

状态：供发明人及专利代理师复核  
对应实现：EvoLex 0.3.0工作树（2026-07-31双层静态可视化增量）  

## 一、发明名称

一种基于来源约束影响域和因果验证凭证的知识图谱候选图补丁验证和版本提交方法、系统、设备及介质。

## 二、技术领域

本方案涉及知识图谱、图数据库完整性控制、数据来源追踪、自然语言处理和软件版本治理，尤其涉及持续知识抽取产生的候选图补丁在正式写图前的固定边界验证、失败操作反事实归因、局部保留和版本化提交。

## 三、要解决的技术问题

### 1. 验证边界随局部排除漂移

候选补丁包含多个实体和关系操作。若发现失败后移除部分操作，并根据剩余操作重新计算影响范围，验证边界可能同步缩小，使原候选补丁曾触及的对象不再参与域外一致性检查。

### 2. 查询关联不等于原因

生成结构查询时附加操作ID只能说明关联。若不在相同基线上排除该操作并重放，就不能判断目标失败是否消失。知识图谱还存在实体操作与依赖该端点的关系操作，单独移除实体会产生新的悬空关系。

### 3. 验证结果与实际提交错配

验证节点可能批准操作集合A，提交节点却收到集合B。同一完整候选补丁在重试或算法升级后也可能形成不同接受集合；若幂等键只有完整patch ID，存储会错误返回首次版本，并使本次凭证看似对应实际写入。

### 4. 上游端点和身份质量问题

实体与关系分步抽取会丢失提及身份；无证据关系引用可能继续传播；链式相似会造成实体过度合并；忽略时间、条件等限定信息会把同一三元组的不同事实错误合并。

### 5. 历史快照回退覆盖后续状态

直接恢复旧快照可能覆盖后来贡献、复活后来删除对象，或删除后来重新创建的新生命周期。

## 四、发明构思

核心不是“Agent做KG”，也不是孤立的联合抽取或最小repair，而是一条强制消费上一步机器数据的控制链：

> 由来源锚和图依赖形成并冻结原始影响域；在固定基线上用依赖闭包排除重放验证失败操作；只在反事实候选空间内求可行排除集合；把基线、边界、原因、求解器和实际接受操作绑定为内容寻址凭证；再以提交清单把凭证和真实图事件绑定到幂等版本事务。

## 五、核心技术方案

### S1：固定基线和来源绑定候选图补丁

系统获取父图版本、规范图基线和候选图补丁。每个更新操作至少具有：

- `operation_id`、`object_type`、`object_id`和`after`；
- 与对象类型相适配的来源锚；
- 声明影响实体、关系、谓词、文档、片段或证据；
- 关系操作的`depends_on_entity_ids`。

实体操作可以由来源文档、片段和提及锚定；关系操作可以由来源文档、证据、源候选和证据文本锚定。当前自动planner只产生来源完整的entity/relation upsert。

### S2：派生并冻结原始影响域

系统合并全部操作的声明影响对象，加入关系端点和基线一跳邻接，形成原始影响域，并对规范序列化结果计算`domain_hash`。后续所有反事实和排除集合重放都使用该冻结域；接受操作自身较小的声明域只作为记录，不替换验证边界。

### S3：固定基线影子结构验证

影子执行器在父版本基线上应用完整候选补丁，至少执行：

- 规范实体存在；
- 关系端点可解析；
- 由端点、谓词和限定信息摘要形成的关系身份唯一；
- 相同输入的确定性重放摘要；
- 排除冻结域对象后的基线/影子域外投影摘要比较。

每个查询保存`query_id`、通过状态、关联操作标识和影响域摘要。

### S4：反事实原因验证

对失败查询的每个关联操作：

```text
closure = DependencyClosure({operation_id})
replay = Apply(baseline, patch - closure, frozen_impact_domain)
if target_query no longer fails:
    operation_id is a counterfactual cause seed
```

若排除实体操作，闭包递归加入依赖该实体端点的关系操作。系统记录操作ID、排除闭包、目标失败是否消失及归因状态。没有通过反事实检查的静态关联不进入求解候选空间。

该因果定义只适用于当前候选补丁和端点依赖闭包，不表示现实世界、统计或知识真实性因果。

### S5：待排除集合和剩余子补丁

在反事实原因及其依赖闭包内搜索待排除更新操作集合`R`：

```text
J(R) = λ1|R| + λ2 B(R) + λ3 Le(R)
```

其中`B(R)`为被排除操作覆盖的实体、关系和谓词数量，`Le(R)`为随排除损失的证据、提及及证据标识数量。约束为依赖闭合、全部结构查询通过及冻结域外投影一致。

候选数不超过16时精确枚举；超过16时重复单项删除和重放直至固定点，结果明确标记为`single_deletion_local_minimum_not_global`，不声称全局或一般集合包含极小。没有失败查询时`R`为空。

### S6：内容寻址因果验证凭证

验证清单至少包括：

- 父版本和基线摘要；
- 完整候选操作摘要；
- 原始/冻结影响域摘要；
- 查询关联、反事实原因和检查记录；
- 求解模式、性质和求解结果摘要；
- 排除操作及接受操作标识；
- 剩余操作摘要和最终影子摘要；
- 证据、重放、域外投影、结构和更新效用门结果。

```text
certificate_id = "cvc-" || SHA-256(CanonicalJSON(validation_manifest))
```

提交判定节点重算完整凭证；提交执行节点再次重算。两者不只比较字符串。凭证是内容寻址一致性清单，不是数字签名，不提供密钥身份认证，也不判断知识真实性。

### S7：提交选择三方一致

提交前强制：

```text
decision.accepted_operation_ids
= evaluation.accepted_operation_ids
= certificate.accepted_operation_ids
```

并核对`decision.certificate_id`。任何不一致均隔离，不调用规范图存储。

### S8：提交清单和幂等版本事务

规范图存储形成：

```text
commit_manifest_hash = SHA-256(CanonicalJSON(
  patch_id,
  parent_version_id,
  sorted(accepted_operation_ids),
  accepted_operations_hash,
  certificate_id
))
```

首次提交在单一事务内校验父版本、写入接受操作、`graph_events`、`graph_versions`和活动指针，并持久化接受操作、凭证ID和提交清单摘要。相同`patch_id`重试只有清单摘要一致才返回旧版本；接受集合或凭证不同则拒绝。

## 六、上游联合抽取和规范化实施例

### 1. 联合提及端点

同一源片段的一次结果包含`mentions`、`relation_candidates`和`evidence_spans`。关系端点引用同批次`mention_id`。跨片段汇总前对提及、关系候选和证据标识加入片段命名空间。

### 2. 证据先行关系引用校验

先检查证据的`evidence_id`、`document_id`和`text`，形成有效证据集合；再检查claim和relation candidate的`evidence_ids`。无效关系候选被移出物化输入，并记录候选ID、缺失字段和无效证据ID。至少一条联合关系成功物化时不进行第二次关系模型调用；零成功时才回退。

### 3. 同类实体合并

只对同类型实体生成提议；自动合并还要求来源提及完整，并检查两个拟合并簇的任意跨簇成员对均达到阈值。实施例中提议阈值0.65、自动阈值0.90、词典别名0.97、缩写0.92。

### 4. 限定关系身份和源断言快照

关系身份由主端点、规范谓词、客端点和限定信息规范序列化摘要组成。不同`valid_year`等限定保持为不同关系。每个聚合关系保存逐条`source_assertions`，包括源ID、源候选、原谓词、端点、限定信息、证据ID/文本、来源片段和源置信度，从而可重建原断言。

## 七、版本贡献和历史补偿实施例

规范存储为实体、别名、提及、关系和证据记录版本贡献，并记录实体/关系删除墓碑。历史补偿创建新版本而不删除旧版本：

1. 逆序读取目标版本事件；
2. 检查每个事件的安全补偿条件；
3. 移除允许移除的目标版本贡献；
4. 根据剩余贡献、较后墓碑和重新创建生命周期重算；
5. 后续依赖不允许移除时记录`skipped_operation_ids`。

本实施例不无条件声称每个历史贡献都可移除，也不自动拆分任意历史误合并簇。

## 八、攻击性验证

当前回归测试覆盖：

- 基线版本被替换；
- 查询—操作映射被替换；
- 求解模式被替换；
- 排除操作集合被替换；
- 最终影子摘要被替换；
- decision接受操作被替换；
- 同patch使用不同接受集合和凭证重试；
- 17个原因候选进入带性质标记的大空间回退；
- 无效关系证据引用被阻断；
- 同三元组不同限定信息不误合并。

任一凭证字段或选择错配会使提交保持隔离；同patch不同清单会在存储层被拒绝。

## 九、主要技术效果

- 冻结域防止局部排除后验证边界收缩；
- 反事实闭包重放把静态关联收紧为可复核原因记录；
- 局部排除保留满足约束的剩余候选知识；
- 两阶段凭证重算检测验证内容和提交选择替换；
- 提交清单使幂等版本与实际接受事件一致；
- 同批次端点和证据先行校验降低关系物化失败；
- 限定关系身份降低不同条件事实误合并；
- 贡献/墓碑补偿保留后续删除和新生命周期。

## 十、可替代实施方式

- 联合抽取器可为生成模型、判别模型、规则或组合；
- 影子环境可为内存图、隔离数据库、临时分支或等效执行环境；
- 摘要可使用满足确定性内容寻址的其他算法；
- 精确求解可使用枚举、ILP、SAT/SMT或约束搜索；
- 规范存储可为关系或图数据库，只要提供父版本和等效原子提交语义；
- Agent可替换为worker、evaluator或普通工作流模块；
- 对抗性部署可在内容摘要外增加HMAC、数字签名、不可变日志或硬件密钥。
- 只读审计层可生成一份当前活动规范图页面以及按来源文档内容快照分别投影的页面；逐文档投影以实体提及和关系证据中的`document_id`为直接边界，只补入已选择关系的主客端点，共享规范实体不据此扩张其他文档独有关系或证据。各页面可把图数据、样式和交互脚本嵌入单一HTML，以在不部署前端服务和后端服务时离线打开。

## 十一、明确边界

当前方案不声称：

- 跨多个独立存储的分布式原子事务；
- 任意业务查询语义等价；
- 任意规模全局最小repair；
- 数字签名或知识真实性证明；
- 在线学习并修改模型权重；
- 任意历史误合并自动拆分；
- 当前项目自有回归语料代表开放域SOTA；
- 当前活动规范图页面代表全部历史对象；
- 逐文档页面是原始抽取图、租户隔离图或权限判定结果；
- `document_id`是文件名、人员身份、租户身份或访问控制主体；
- 自包含HTML提供不可篡改、密码学完整性或合规证明。

## 十二、商业化场景

- LLM/RAG知识库写入网关；
- 企业知识图谱变更控制面；
- 数据目录、主数据和图数据库治理；
- 科研、制造、运维、法规或专利情报的审计型KG；
- 按图版本导出来源、原因、排除集合、凭证和提交清单的合规证据包；
- 在受限网络或客户内网中交付无需部署服务的KG复核页面，以逐文档页面缩小人工证据检查范围，并由全局页面提供跨来源活动对象概览。
